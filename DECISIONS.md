# Architecture Decision Log

| Date | Decision | Alternatives considered | Why |
| ---- | -------- | ----------------------- | --- |
| 2026-10-08 | FastAPI over Django | Django REST Framework, Flask | FastAPI gives async-first, auto-generated OpenAPI docs, and Pydantic v2 natively. Much less boilerplate for an API-only backend. |
| 2026-10-08 | SQLite typed answer columns (value_text, value_number, value_bool) | Single JSON blob column | Typed columns allow GROUP BY / aggregate queries (avg rating, min/max number) without JSON parsing; better for the Results summary endpoint. |
| 2026-10-08 | answer_options join table | Storing chosen option ids as JSON in answers.value_text | Join table makes per-option response counts a simple `GROUP BY option_id` query instead of string parsing; normalized. |
| 2026-10-08 | JSON for settings and theme | Separate typed columns per field | question.settings fields differ per type (rating_max, number_min/max, allow_multiple). A JSON column avoids a sparse wide table and these fields are never queried in WHERE clauses. |
| 2026-10-08 | nanoid 10-char public_id on forms | UUID, sequential id | Hides internal DB ids from public URLs, hard to enumerate, short enough for shareable links. |
| 2026-10-08 | Service-layer architecture (routers thin, services hold logic) | Fat controllers / Active Record | Separation of HTTP concerns from business logic makes unit testing, reuse, and future auth changes easier. Routers become testable independently from service functions. |
| 2026-10-09 | Form response_count via single aggregate subquery | N+1 queries when loading dashboard | Outerjoin with func.count() avoids N+1 queries for the dashboard list endpoint. |
| 2026-10-09 | model_fields_set for partial PATCH | Setting fields to None by default | Explicitly tracking fields_set ensures missing fields don't overwrite existing db fields with nulls. |
| 2026-10-09 | Optimistic UI updates with TanStack Query | Waiting for API response | onMutate updates the local cache before network roundtrips complete for renaming, deleting, and publishing forms, reducing perceived latency. |
| 2026-10-09 | Returning Response directly for 204 | Using status_code=204 decorator + JSONResponse | Newer FastAPI strict validation throws AssertionErrors if body is theoretically possible for 204. Returning `Response(status_code=204)` fixes this while retaining standard 404 bodies. |
| 2026-10-09 | Autosave implementation in Builder | Explicit save button | Saves changes optimistically using TanStack Query. Reduces user friction and ensures no lost work. Unload prevention ensures network has time to complete saves. |
| 2026-10-09 | @dnd-kit for drag and drop | react-beautiful-dnd | @dnd-kit is modern, modular, accessible and actively maintained. `react-beautiful-dnd` is essentially unmaintained now. |
| 2026-10-09 | Shared QuestionView for builder and player | Separate components | The spec says "renders the selected item exactly the way the respondent will see it". A shared component ensures pixel-perfect fidelity between the builder preview and the final respondent view. |
| 2026-10-09 | Preserve local question ordering invariants | Trust server positions after each optimistic mutation | Normalizing positions after add/delete/reorder keeps numbering contiguous during optimistic UI updates and avoids transient gaps or duplicates. |
| 2026-10-09 | Add autosave retry at the builder boundary | Hide failures until the next edit | Exposing a retry callback from the autosave hook lets the top bar recover a failed save without requiring a second edit, while keeping the existing debounced persistence model. |
| 2026-10-09 | Give the settings panel an explicit bounded shell and scrolling body | Let the panel grow with its option editor | A fixed full-height panel with a non-scrolling type header and `min-height: 0` scrolling body keeps long settings accessible without resizing the canvas or editor shell. |
| 2026-10-09 | Keep pending debounce timers across unrelated builder mutations | Cancel every timer during any form-state effect cleanup | Creating or reordering a question should not cancel a pending title or description save; timer cleanup is limited to unmount while newer relevant edits still reset the debounce window. |
| 2026-10-09 | Use a pure reducer for respondent navigation | Local component state spread across event handlers | A single state machine makes direction, screen transitions, answer persistence, validation errors, response identity, and a future Phase 6 jump action deterministic and unit-testable. |
| 2026-10-09 | Use vertical slide plus fade with reduced-motion fallback | Horizontal-only transitions or instant screen replacement | Vertical movement matches the reference respondent flow; Framer Motion's reduced-motion signal removes translation and keeps only a short fade for accessibility. |
| 2026-10-09 | Duplicate validation on client and server | Client-only validation or server-only round trips | Client validation provides immediate inline feedback while server validation remains authoritative for untrusted public requests and transaction safety. |
| 2026-10-09 | Keep public POST abuse protection in process | Redis or a distributed edge limiter | This single-process SQLite demo needs a dependency-free baseline; the limitation is documented and production deployments should move the limit to a shared edge/Redis layer. |
| 2026-10-09 | Compute results statistics in SQL | Loading every response and counting in Python | Aggregates and `GROUP BY` queries use the typed answer columns and normalized `answer_options` table efficiently while preserving cross-form scoping. |
| 2026-10-09 | Stream CSV exports and protect formula cells | Building the entire CSV in memory or returning raw cells | A generator-backed `StreamingResponse` keeps exports bounded, while prefixing cells beginning with `=`, `+`, `-`, or `@` prevents spreadsheet formula injection. |
| 2026-10-09 | Evaluate logic against the first matching rule and restrict destinations to later questions/end | Arbitrary graph traversal and client-only rules | Ordered destinations make cycles impossible, preserve predictable respondent paths, and let the server recompute the visited path before enforcing required questions. |
| 2026-10-09 | Keep response storage statuses as partial/completed and derive abandonment from inactivity | Adding a third persisted status | A 30-minute cutoff preserves the existing API/status contract while reporting stale partials accurately in summaries. |
| 2026-10-09 | Store theme presentation values as JSON and expose them as CSS-in-JS variables in the player | Per-component hard-coded colour overrides | The existing JSON theme column is appropriate for presentation-only settings and lets public forms apply creator styling without schema expansion. |
| 2026-10-09 | Validate optional query parameters on results endpoints (days, from, to, status, q, sort) | Unvalidated raw SQL/string parameters | Pydantic and FastAPI Query validators guarantee type safety and bounds (e.g. days 1..90) across GET /summary, GET /stats, and GET /responses. |
| 2026-10-09 | New GET /forms/{id}/responses/export endpoint (format=csv\|xlsx, ids, status, from, to, q) | Keep only the legacy export.csv path | Keeps backward compat via the legacy endpoint while adding XLSX support, row-selection ids, and all filter params. Logged in DECISIONS.md per global rules. |
| 2026-10-09 | CSV exports use UTF-8 BOM, new column order (#, questions, Response Type, Start Date, Submit Date, Ending), and YYYY-MM-DD HH:mm:ss date format | ISO 8601 timestamps (Excel parses as minutes:seconds) | BOM ensures Excel auto-detects UTF-8; human-readable timestamps avoid the 54:56.6 Excel bug; new column order matches Typeform parity spec. |
| 2026-10-09 | XLSX built with openpyxl in memory (bold header, frozen row, auto-width columns) | Streaming XLSX or CSV-only | openpyxl is a well-maintained pure-Python library. In-memory build is acceptable for the response counts in this demo; frozen header and auto-width match Excel best practices. |
| 2026-10-09 | Response drawer sits beside the table (not a full overlay), uses URL ?response=ID for state | Fixed overlay drawer covering the table | Beside-table layout allows reading both table and drawer simultaneously; URL state means a refresh keeps the drawer open. |
| 2026-10-09 | One column per question in the responses table (not just first three) with QuestionTypeBadge headers | Fixed three-column preview + Answers count | All question data is immediately visible in a horizontally scrollable table, matching Typeform parity spec F.2. |
